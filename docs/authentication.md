# Authentication

Requests and responses use JSON. Routes have no trailing slash. Authentication uses the Django
`sessionid` HttpOnly cookie. Fetch requests must include cookies with `credentials: 'include'`.

1. GET `/v1/auth/csrf` to receive a CSRF cookie and `{csrfToken}`.
2. Send `X-CSRFToken: <csrfToken>` on every POST, including anonymous signup/login.
3. Login rotates session and CSRF tokens. Fetch CSRF again before subsequent POST requests.
4. Use GET `/v1/users/me` for the current database-backed identity.

| Method | Route | Input | Success |
| --- | --- | --- | --- |
| GET | `/v1/auth/csrf` | — | 200 `{csrfToken}` |
| POST | `/v1/auth/signup` | email, password, passwordConfirmation, optional displayName | 202 generic acceptance |
| POST | `/v1/auth/confirm-email` | token | 200 confirmation |
| POST | `/v1/auth/login` | email, password | 200 user |
| POST | `/v1/auth/logout` | empty object | 200, session invalidated |
| POST | `/v1/auth/password-reset` | email | 202 generic acceptance |
| POST | `/v1/auth/password-reset/confirm` | uid, token, password, passwordConfirmation | 200 password updated |
| GET | `/v1/users/me` | session cookie | 200 user |

User: `{id, email, displayName, role}`, where role is `USER` or `ADMIN` from database staff status.
Unknown fields are rejected. Emails normalize to lowercase; passwords retain whitespace, require
at least ten characters and pass Django's password validators. Password confirmation is server-checked.
Signup creates an inactive identity with an unusable password. Each signup attempt stores its own
password hash and profile; its signed confirmation expires after 24 hours and is one-use. Confirmation
atomically installs only that attempt's credentials and discards other pending attempts. Repeated signup
returns generic acceptance and cannot change a confirmed or provisioned account. Only follow the link
for the signup attempt you requested. Reset expires after one hour and invalidates prior sessions.

API failures: `{code, message, requestId}`. `X-Request-ID` is generated by the server.
Anonymous/invalid credentials return 403; validation/token errors return 400; rate limits return 429
with `Retry-After`. Auth responses are private/no-store. Detailed validation/provider errors are not exposed.

Local limits per source IP: login 10/minute, signup 3/hour, reset 3/hour. Forwarded IP headers are
ignored. Django's local memory cache is per process and does not provide strict distributed quotas.
Generic responses reduce direct account disclosure; timing is not guaranteed identical.

Local mail is stored beneath ignored `.local/mail` in a private directory. Tests use an in-memory
backend. Confirmation/reset URLs target frontend pages that still need implementation; API tests
exercise their payloads directly. No browser login UI is included here.

## Staff accounts

Use `python manage.py createsuperuser` interactively with the runtime database configuration.
This is a trusted local administration action; never expose it as a public signup parameter.
Serve `/admin/` through HTTPS with the production cookie policy, static assets and restricted access.
